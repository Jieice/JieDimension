# 📁 文件管理指南

正确管理项目文件，保持仓库精简高效。

---

## 🎯 基本原则

### ✅ 应该放在项目里的

| 文件类型 | 说明 | 示例 |
|---------|------|------|
| **Markdown 文章** | 文本文件很小 | `_posts/*.md` |
| **配置文件** | 必需的项目配置 | `_config.yml` |
| **优化后的图片** | < 500KB | 游戏截图、图标 |
| **CSS/JS** | 样式和脚本 | `assets/css/main.css` |
| **小音频** | < 1MB | 按钮音效（如需要） |

### ❌ 不应该放在项目里的

| 文件类型 | 原因 | 替代方案 |
|---------|------|----------|
| **游戏安装包** | 太大（几十MB到几GB） | 👉 使用外部链接 |
| **游戏源码** | 不需要在网站展示 | 👉 单独的私有仓库 |
| **高清视频** | 严重拖慢仓库 | 👉 YouTube/B站 |
| **未压缩图片** | 浪费空间 | 👉 先压缩再上传 |
| **临时文件** | 无用垃圾 | 👉 .gitignore 排除 |

## 🎮 游戏文件管理策略

### 游戏安装包

**❌ 错误做法**：
```
assets/games/
  ├── horror-game.exe      # 500MB - 太大！
  ├── mobile-game.apk      # 100MB - 不要！
  └── game-assets.zip      # 1GB - 绝对不行！
```

**✅ 正确做法**：

1. **上传到 GitHub Releases**（推荐）
   ```
   仓库 → Releases → Create a new release
   上传游戏安装包
   复制下载链接
   ```

2. **使用云存储**
   - OneDrive / Google Drive / 百度云
   - Itch.io（免费游戏托管平台）
   - TapTap（手机游戏）
   - CrazyGames（HTML5游戏）

3. **在游戏页面添加外部链接**
   ```markdown
   ---
   links:
     - text: 下载游戏（Windows）
       url: "https://github.com/xxx/releases/download/v1.0/game.exe"
       external: true
   ---
   ```

---

### 游戏截图

**✅ 可以放在项目里**（如果优化过）

1. **图片优化**：
   - 使用工具压缩：TinyPNG.com
   - 目标大小：< 300KB 每张
   - 推荐格式：JPG（照片）、PNG（透明背景）

2. **存放位置**：
   ```
   assets/images/
   ├── horror-game/
   │   ├── screenshot-1.jpg    # 250KB ✓
   │   └── screenshot-2.jpg    # 280KB ✓
   └── mobile-game/
       └── gameplay.jpg         # 320KB ✓
   ```

3. **引用方式**：
   ```markdown
   ![游戏截图](/JieDimension/assets/images/horror-game/screenshot-1.jpg)
   ```

---

### 游戏视频

**❌ 不要放在项目里**

**✅ 使用视频平台**：

1. **上传到视频平台**：
   - YouTube
   - Bilibili（B站）
   - 优酷

2. **在网站中嵌入**：
   ```markdown
   ## 游戏演示
   
   [观看演示视频](https://www.youtube.com/watch?v=xxx)
   
   或使用 iframe 嵌入：
   <iframe width="560" height="315" 
     src="https://www.youtube.com/embed/xxx">
   </iframe>
   ```

## 📊 项目大小监控

### 检查仓库大小

```bash
# 查看仓库大小
git count-objects -vH

# 查看大文件
git rev-list --objects --all | \
  git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | \
  awk '/^blob/ {print substr($0,6)}' | sort -n -k 2
```

### 理想的仓库大小

| 项目阶段 | 仓库大小 | 说明 |
|---------|---------|------|
| **初期** | < 10MB | 几篇文章 + 几张图片 |
| **成长期** | 10-50MB | 多个游戏 + 优化图片 |
| **成熟期** | 50-100MB | 大量内容但图片优化好 |
| **⚠️ 警告** | > 100MB | 需要清理大文件 |

## 🧹 清理大文件

### 如果误传了大文件

1. **从最新提交删除**：
   ```bash
   git rm --cached 大文件.exe
   git commit -m "删除大文件"
   git push
   ```

2. **从历史记录彻底删除**：
   ```bash
   # 使用 BFG Repo-Cleaner（推荐）
   java -jar bfg.jar --delete-files 大文件.exe
   git reflog expire --expire=now --all
   git gc --prune=now --aggressive
   git push --force
   ```

## 📝 最佳实践

### ✅ 每次提交前检查

```bash
# 查看即将提交的文件
git status

# 查看文件大小
ls -lh 文件名
```

### ✅ 图片上传流程

1. **压缩图片**：使用 TinyPNG.com
2. **检查大小**：确保 < 500KB
3. **放入正确文件夹**：`assets/images/游戏名/`
4. **提交推送**

### ✅ 定期清理

- 每月检查仓库大小
- 删除不需要的旧文件
- 重新优化较大的图片

## 🎯 具体案例

### 案例1：发布新游戏

```
步骤：
1. 游戏打包 → horror-game.exe (500MB)
2. ✅ 上传到 GitHub Releases
3. ✅ 复制下载链接
4. ✅ 创建游戏截图（3张，每张 < 300KB）
5. ✅ 上传截图到 assets/images/horror-game/
6. ✅ 创建 _games/horror-game.md，添加下载链接
7. ✅ 运行 deploy.bat

✅ 仓库增加：<1MB（只有截图）
❌ 不是：+500MB（如果把游戏放进来）
```

### 案例2：写开发日志

```
步骤：
1. 创建 _posts/2025-10-06-devlog.md
2. 写文章（文本）
3. 添加配图（压缩后 < 300KB）
4. 运行 deploy.bat

✅ 仓库增加：< 500KB
```

## ⚠️ 注意事项

1. **GitHub 文件限制**：
   - 单个文件 < 100MB
   - 推荐单个文件 < 50MB
   - 仓库总大小 < 1GB

2. **网站加载速度**：
   - 图片越大，加载越慢
   - 手机用户流量有限
   - 优化图片 = 更好的用户体验

3. **备份策略**：
   - 游戏源码单独备份
   - 不要依赖 Git 存储大文件
   - 使用专业的云存储

## 🆘 常见问题

**Q: 我可以把游戏源码放在项目里吗？**  
A: ❌ 不推荐。创建单独的私有仓库，或使用本地备份。

**Q: 10MB 的图片可以吗？**  
A: ❌ 太大了，压缩到 < 500KB。

**Q: 怎么知道文件是否被忽略？**  
A: 运行 `git status`，被忽略的文件不会显示。

**Q: 误传大文件怎么办？**  
A: 看本文档的"清理大文件"部分。
